Reading the simulator like a real calculator

This manual documents the T2PREP Calculator, a playable TI-84 Plus CE simulator with all 14 T2PREP routines wired up as real, runnable programs. It assumes nothing about the math — that's covered by the companion field guide — and instead answers one question per program: what do I press, in what order, and what comes back?

Every worked example below was run step by step against the actual program code, not idealized — where the real screen output is rougher than a textbook answer (a decimal instead of a fraction, an explicit "1" coefficient a textbook would drop), that's called out rather than cleaned up.

CHAPTER 0general mechanics

How input and output work

The screen is 26 characters wide and 10 lines tall — real TI-84 dimensions. A line that runs long gets cut off with "…", so every program's own messages are kept short; your typed input can run longer and will wrap or scroll within the entry line as needed.

The keypad

Click a key, or click the calculator once to focus it and then type on your physical keyboard — digits, + - * /, parentheses, ,, Enter, Backspace (= DEL), Escape (= CLEAR), arrow keys, and the letter x for the variable X all work directly. 2ND then a key gives its blue label (shown above the key); ALPHA then a key gives its green label. Both are toggles — press once to arm, then press the next key.

Negative numbers: there are two different minus-looking keys. (−) means "this number is negative" and goes before a value with nothing in front of it (the start of a list entry, right after a comma, right after {). − is subtraction and goes between two values. Clicking the wrong one is the single most common mis-entry on this simulator. Typing a physical keyboard's - key is smarter — it figures out which one you mean from context.

Single-value input — Prompt

When a program needs one number per variable, it shows A=? (or whatever letter), waits for digits and ENTER, then moves to the next one. You can type a full expression, not just a digit — 1/5 or 2nd[√]9 both evaluate before being stored.

List input — coefficients, zeros, multiplicities

Several programs ask for a whole set of numbers at once, shown as e.g. COEF {a,..,c}=?. Type an actual list literal: 2ND{ then each value separated by ,, closed with 2ND}, then ENTER — e.g. {5,-14,-26,8}. Coefficient lists always run highest degree first, same convention a textbook uses for synthetic division.

Expression input — typing a function of X

Three programs (RATSLV, SIGNCH, CHECK) ask you to type real math using X as the variable, e.g. 5X³-X²-35X+7. This isn't read as text — the simulator's real expression engine parses and evaluates it later at whatever value of X the program needs, the same engine the calculator's home screen uses. A malformed expression won't be caught until it's evaluated, so if a program later shows ERR:SYNTAX, the expression was the problem.

Menus

A titled list of choices appears full-screen. Use ▲/▼ then ENTER, or press the number key next to the option directly. The screen returns to exactly where the program left it once you choose.

Staged output — Pause

Most programs print a first batch of lines, then freeze with a dim, non-blinking busy indicator in the status bar. That's a Pause — press ENTER to let the rest print. It exists so the screen doesn't fill and scroll past an intermediate step before you've read it.

Errors

A bad input (dividing by zero, a negative under an even root, a syntax mistake) stops the program and shows ERR:MESSAGE with 1:Quit / 2:Goto. 1 (or ON) returns to the home screen; 2 opens the program's listing so you can see what it was trying to do. Press ON at any time to interrupt a running program early.

PRGM SLOT 8ZCHAIN

ZCHAIN

Given one zero $k$, divides it out and solves whatever's left for the rest of the zeros.

Internally this is SYNDIV feeding straight into the same solver QUADSV uses, chained automatically. If the remainder isn't zero, $k$ wasn't actually a root and the program stops there.

PRGM SLOT 10RATSLV

RATSLV

Checks candidate solutions to a rational equation against both sides, flagging any that make a denominator zero.

This is a checker, not a solver — it doesn't clear denominators or find roots on its own. Solve the equation by hand first (or guess integer candidates), then hand RATSLV the candidate list; it plugs each one into both your typed expressions and reports a match, a mismatch, or "undefined" (an extraneous solution).

PRGM SLOT 11SIGNCH

SIGNCH

Builds a real sign chart for $f(x)$ against a set of critical values and an inequality direction.

You supply $f(X)$ as a typed expression and the critical values (zeros of the numerator and, for a rational inequality, the denominator too). SIGNCH tests a real point in every region — it genuinely evaluates your expression, it doesn't just pattern-match multiplicities the way a shortcut rule would.

PromptsOutput
f(X) expression, CRIT VALUES list, then a 4-way menu for the inequality signpause → each region's sign and whether it's kept → the solution in interval form
PRGM11 (−)4X(X+2)x²(5−X)ENTER {(−)2,0,5}ENTER 1(f(x)>0)
Worked example — key 41f: −4u(u+2)²(5−u)>0
TI-84 PLUS CERUN
[Pause — press ENTER] (-∞,−2) + ✓ (−2,0) + ✓ (0,5) - (5,∞) + ✓ SOLUTION: (-∞,−2) U (−2,0) U (5,∞)
The $(-2,0)$ region reads positive even though $x=-2$ is a critical value of even multiplicity — SIGNCH tests the open interval next to it, not the point itself, so it shows the true sign on both sides of a touch-point correctly.
